# AI-005 · Prisma schema aligned with class model v6.3

- **Date and tool** · 2026-11-24. Claude Opus 5.5 (Claude Code CLI, model ID `claude-opus-5-5`). Role: apply a specified schema change, generate the initial migration, run the checks and prepare the commits and PR.
- **Task** · Align `prisma/schema.prisma` with class model v6.3 and add the first migration. There is no database yet, so the migration is generated offline.
- **Prompt, paraphrased** · Daniel drafted the prompt with Claude (claude.ai chat) before running it in Claude Code. On a new branch from develop, change only these fields: `LevelProgress` drops `stars` and gains `data Json @default("{}")`; `Score` gains `moves Int` and `elapsedMs Int`; `Level` gains `board Json` and `schemaVersion Int @default(1)`, and `difficulty` becomes optional. Generate `prisma/migrations/<timestamp>_init/migration.sql` with `prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script` and add `migration_lock.toml`. Run validate, generate, lint, test and build. Fix only what this change breaks. Show the diff before pushing.
- **Inputs** · Class model v6.3 (`docs/diagrams/README.md`), the existing schema and Daniel's list of field changes.
- **Output** · The schema change (7 field lines plus the column realignment in `Level`), `prisma/migrations/20261125020329_init/migration.sql` and `prisma/migrations/migration_lock.toml`. Delivered in [PR #13](https://github.com/hexablock-g5-ucab/hexablock-api/pull/13).
- **Human contribution** · Daniel decided every field change, reviewed the schema diff before the migration was generated, rejected the use of `git stash` to compare against develop, and first chose to continue without a local test run, then installed Node 24.22.3 so the tests and the pre-push hook ran locally. He also required that the build artefact `tsconfig.build.tsbuildinfo` stay out of every commit.
- **Verification** · `prisma validate` and `prisma generate` (Prisma 6.19.3) passed, as did `npm run lint` and `npm run build`. `npm test` first failed locally on Node 22.19.0: the repository requires Node 24 (`.nvmrc`), and Jest cannot load the `@nestjs/testing` ES module without Node 24.9+. After Daniel installed Node 24.22.3, `npm test` passed locally (1/1), and the lefthook pre-push hook ran the tests before the push. The migration was not applied to PostgreSQL because there is no database yet.
- **Lesson and limitation** · Without dependencies installed, `npx prisma` downloaded an unrelated Prisma 8 release candidate, which did not produce a usable migration. Installing the declared dependencies first made the project's own Prisma 6 CLI available. The repository has no lockfile, so a local install resolves newer versions than CI may use.
- **Attribution** · The assistant typed the schema lines exactly as Daniel specified them. The Prisma CLI generated the migration SQL, which is excluded from the product-code count as a generated file. Product code changed: schema only, about 8 lines.
