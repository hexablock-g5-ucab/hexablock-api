- **Lesson and limitation** · On a full tie, the default ranking keeps the order in which the repository returns entries, and the port does not fix that order. The adapter should return a deterministic order (for example by `createdAt`, then id) so a full tie does not reorder between requests. The contract's `ScoreEntryResponseDto` has an `id` that the v6.3 `ScoreEntry` lacks; UC-102 lists this as an open question for the controller PR. The assistant chose details that the model does not fix, such as rejecting a non-positive limit with `RangeError`, filtering again in the use case and the immutability approach, and listed them for review.
