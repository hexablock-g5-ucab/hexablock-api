- **Lesson and limitation** · The port has separate `find` and `save` calls, so the use case alone cannot make a sync atomic. The port documents that the adapter must prevent a concurrent sync from lowering stored progress, but a policy-merged `data` field can still follow the last writer unless the adapter runs the whole read-merge-write in one transaction. The adapter PR has to settle this, possibly with a port change. The assistant chose details that the model does not fix, such as level ordering and folding of repeated levelIds, and listed them for review. Applying the "incoming replaces stored" rule literally would have let an empty `{}` from a fresh install wipe stored data. Daniel caught this in review.
