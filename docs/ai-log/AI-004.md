# AI-004 · Class model v6.3 and complete README diagram

- **Date and tool** · 2026-11-23. Claude Opus 5.5 (claude.ai) drafted the model, diagrams and prose. Gemini (exact model not shown by the interface) reviewed the drafts. Role: design iteration, diagram generation and documentation editing.
- **Task** · Take the v5 model to v6.3. Close the team's edge-case decisions for the three games, prepare the design so a new variant can be added without changing existing code (statement points 2 and 3.1–3.3), and publish one complete class diagram per repository in its README.
- **Prompt, paraphrased** · Apply the team's rule decisions to the class model without DDD. Find what would force changes to existing code when a new variant is added, and fix it with new interfaces. Then merge the views into one diagram per repository for the README.
- **Inputs** · Project statement, the v5 model, the professor's consultation notes, the team's edge-case decisions and the repository state.
- **Output** · The REST API view and one complete API diagram (with a zoomable SVG), the model index and the README architecture and class-model section.
- **Human contribution** · Daniel directed each iteration and accepted or rejected each proposal. The team decided the game rules and voted to drop saving unfinished games. Gemini's review found four issues that were fixed in v6.2 and v6.3:
  - a dependency from the application layer to Flutter;
  - a level director that could not reach builder-specific steps;
  - an unsafe generic renderer;
  - a missing queue for pending scores.
- **Verification** · A coherence script checks every view: undeclared types, relations to missing classes and layer tags. Each image was rendered and inspected. The README links were checked against the files.
- **Lesson and limitation** · A large merged Mermaid diagram exceeds the default 50,000-character limit and renders empty without warning. `mmd-config.json` raises the limit. Dart generics are covariant but unsound, so a renderer typed for one cell type compiled and would have failed at runtime. The design now closes generics inside each game module.
- **Attribution** · AI-assisted model and prose based on team decisions. Product code changed: none. Exclude this documentation task from the product-code denominator.
